## 3. 코드베이스 분석 결과

### 3.1 프로젝트 성격

이 프로젝트는 Java 17, Spring Boot, Thymeleaf 기반의 고객 피드백 분석 웹 애플리케이션이다.

사용자는 피드백을 직접 입력하거나 CSV 파일로 업로드할 수 있으며, 시스템은 키워드 규칙을 기반으로 감정과 카테고리를 분석한다. 분석 결과는 화면에서 통계로 확인할 수 있고, 필터링된 결과는 CSV로 다운로드할 수 있다.

동시에 이 프로젝트는 리팩토링 챌린지 성격을 가진다. `project_purpose.md`에 따르면 현재 코드는 의도적으로 구조화되지 않은 코드, 중복 로직, 잘못된 책임 분배, 전역 상태, 테스트 부족 등을 포함한다.

### 3.2 기술 스택

- Java 17
- Spring Boot 3.5.3
- Spring MVC
- Thymeleaf
- Maven
- OpenCSV
- JUnit / Spring Boot Test

### 3.3 핵심 기능

- 웹 대시보드 제공
- 텍스트 피드백 입력
- CSV 업로드
- 키워드 기반 감정 분석
- 키워드 기반 카테고리 분석
- 감정/카테고리 기준 필터링
- 분석 결과 시각화
- 필터링 결과 CSV 다운로드

### 3.4 주요 실행 흐름

1. `GET /`: 초기 화면 렌더링 및 현재 피드백 목록 표시
2. `POST /analyze`: 수동 입력 피드백 추가 및 분석
3. `POST /upload`: CSV 파일 업로드 및 피드백 목록 추가
4. `POST /filter`: 감정/카테고리 조건 기반 필터링
5. `GET /download`: 마지막 필터링 결과 CSV 다운로드

## 4. 주요 문제점

### 4.1 전역 상태 사용

`Session`, `TextAnalyzer`, `FeedbackController.fil_data`가 static 또는 인스턴스 상태에 의존한다. 이 구조는 사용자별 세션 분리, 동시 요청 처리, 테스트 격리에 불리하다.

### 4.2 중복된 분석 규칙

감정 분석 키워드와 판정 로직이 `Constants.java`, `TextAnalyzer.java`, `Filters.java`에 분산되어 있다. 키워드 변경 시 여러 파일을 수정해야 하며, 분석 결과와 필터링 결과가 달라질 위험이 있다.

### 4.3 컨트롤러 책임 과다

`FeedbackController.java`가 요청 처리뿐 아니라 CSV 저장/파싱, 상태 갱신, 분석 호출, 필터링 결과 관리, 다운로드까지 담당한다. 서비스 계층으로 책임을 분리할 필요가 있다.

### 4.4 약한 도메인 모델

`Feedback.java`에는 `sentiment`, `category` 필드가 있으나 실제 분석 결과 저장에 사용되지 않는다. 분석 결과를 명시적인 도메인 모델 또는 결과 객체로 표현하는 개선이 필요하다.

### 4.5 CSV 처리 취약점

CSV 업로드 로직은 `C:\tmp` 경로와 원본 파일명에 의존한다. 또한 `text` 헤더 검증, 컬럼 존재 여부 검증, 파일명 안전성 검증이 부족하다.

### 4.6 테스트 부족

현재 테스트는 `contextLoads()` 수준에 머물러 있다. 감정 분석, 카테고리 분석, 필터링, CSV 파싱, 컨트롤러 흐름에 대한 테스트가 필요하다.

## 6. 작성한 .cursorrules 요약

`.cursorrules`에는 이후 AI 작업 시 지켜야 할 핵심 기준만 압축해 작성했다.

주요 내용:

- 이 프로젝트는 고객 피드백 분석기이자 리팩토링 챌린지임을 명시
- 핵심 사용자 흐름을 보존할 것
- 감정 값은 `긍정`, `중립`, `부정`으로 유지
- 카테고리는 `배송`, `품질`, `가격`, `서비스`, `사용성`으로 유지
- 컨트롤러에서 비즈니스 로직을 분리할 것
- 분석/필터링 규칙을 단일 출처로 관리할 것
- 새 static mutable state를 추가하지 말 것
- 새 코드에는 명확한 도메인 타입과 테스트 가능한 서비스 구조를 우선할 것
- 분석, 필터링, CSV 처리 변경 시 테스트를 추가할 것

## 7. 권장 후속 작업

1. `TextAnalyzer`와 `Filters`의 중복 감정 판정 로직 통합
2. `Sentiment`, `Category`, `AnalysisResult` 같은 명시적 도메인 타입 도입
3. `FeedbackController`의 분석/필터링/CSV 책임을 서비스로 이동
4. `Session` static 상태 제거 또는 사용자별 상태로 격리
5. 감정 분석, 카테고리 분석, 필터링 로직 단위 테스트 추가
6. CSV 업로드 검증과 에러 메시지 개선
7. `index.html`을 Thymeleaf fragment 기반으로 점진 분리
