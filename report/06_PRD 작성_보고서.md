## 2. 작성 목적

이번 세션의 목적은 Phase 4에서 정의한 Epic, Story, Gherkin, 체크리스트를 기준으로 피드백 분석 시스템의 PRD를 구조화하는 것이다.

PRD는 구현 지시서가 아니라 제품 요구사항 문서로 작성되며, 입력 계약, 출력 계약, 테스트 가능한 인수 기준, 회귀 보호 규칙을 명확히 고정한다.

## 6. 산출물 요약

### 6.1 프로젝트 개요

PRD는 고객 피드백을 수동 입력 또는 CSV 입력으로 받아 감정과 키워드 기준으로 분석하고, 시각화와 CSV 다운로드 결과를 제공하는 시스템을 대상으로 한다.

### 6.2 기능 요구사항

| 구분 | 기능 |
|---|---|
| 필수 | 입력 검증 |
| 필수 | CSV 출력 및 다운로드 |
| 필수 | 키워드 유무 기반 피드백 분류 |
| 필수 | 감정 분석 |
| 필수 | 피드백 필터링 및 검색 |
| 필수 | 분석 결과 시각화 |
| 권장 | OCP 레지스트리 기반 분석 규칙 확장 |
| 권장 | 동적 분석 단위 등록 |
| 선택 | 잘못된 JSON/YAML 설정 파일 오류 보고 |

### 6.3 입력 및 출력 계약

| 영역 | 계약 |
|---|---|
| 수동 입력 | 비어 있지 않은 피드백 텍스트를 분석 대상으로 수용 |
| 빈 입력 | 저장하지 않고 기존 분석 결과 유지 |
| CSV 입력 | 첫 행에 `text` 헤더 필요 |
| 감정 분석 | `"긍정"`, `"부정"`, `"중립"` 중 하나로 집계 |
| 키워드 분류 | `"배송"`, `"품질"`, `"가격"`, `"서비스"`, `"사용성"` 기준으로 집계 |
| CSV 다운로드 | UTF-8 CSV, 첫 행 `text`, 필터 결과 행 포함 |

### 6.4 성공 지표

- [ ] `"복숭아 최고"` 입력 시 감정 결과가 `"긍정"`으로 집계되고 키워드 카테고리 카운트는 증가하지 않는다.
- [ ] 빈 입력 또는 공백-only 입력 시 피드백이 저장되지 않고 기존 분석 결과가 유지된다.
- [ ] `text` 컬럼이 포함된 CSV 업로드 시 각 행이 피드백으로 수용되고 분석 결과에 반영된다.
- [ ] 감정 `"부정"`과 키워드 `"가격"` 필터를 함께 적용하면 두 조건을 모두 만족하는 피드백만 표시된다.
- [ ] CSV 다운로드 시 첫 행은 `text`이고 한글 피드백은 UTF-8로 보존된다.
