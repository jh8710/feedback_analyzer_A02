# Feedback Analyzer PRD

## 1. 프로젝트 개요

### 1.1 한 줄 목적문

고객 피드백을 입력하는 학습자가 수동 입력 또는 CSV 입력으로 피드백을 제공하면, 시스템은 감정과 키워드 기준으로 분석하고 시각화 및 CSV 다운로드 결과를 제공한다.

### 1.2 배경 및 문제 정의

현재 피드백 분석 흐름은 입력, 분석, 필터링, 출력 책임이 한 흐름에 강하게 결합되어 있어 입력 계약과 오류 정책을 테스트로 고정하기 어렵다.

현재 코드 구조는 단일 진입 흐름과 조건 분기 중심 처리에 의존하므로 다음 문제가 발생한다.

- 빈 입력, CSV 형식 오류, 알 수 없는 값 입력의 처리 기준이 명시적으로 추적되지 않는다.
- 감정 분석, 키워드 분류, 필터링, 시각화, 다운로드의 책임 경계가 흐리다.
- 키워드 또는 감정 규칙이 변경될 때 기존 결과가 깨지는 회귀를 탐지하기 어렵다.
- Phase 4 Gherkin의 Background와 Story Acceptance Criteria를 기준으로 계약을 고정할 필요가 있다.

### 1.3 목표

- 수동 입력과 CSV 입력의 입력 계약을 100% 문서화하고, 필수 입력 실패 조건을 인수 기준으로 고정한다.
- 핵심 도메인 로직 라인 커버리지 80% 이상을 목표로 한다.
- 입력 검증, 분류, 감정 분석 주요 분기 커버리지 90% 이상을 목표로 한다.
- 수동 입력, CSV 입력, 필터링, CSV 다운로드 계약 테스트를 모두 통과 대상으로 정의한다.
- 공개 동작 변경 시 Story Acceptance Criteria와 Gherkin Scenario 갱신 없이는 병합하지 않는다.

### 1.4 비목표

- 자연어 처리 모델의 정확도 개선은 Phase 4 범위에 포함하지 않는다.
- 코드, 클래스 설계, 빌드 스크립트 작성은 본 PRD 범위에 포함하지 않는다.
- 저장소 범위 밖의 단위 변환 기능 구현은 포함하지 않는다.

## 2. 사용자 및 이해관계자

### 2.1 타깃 사용자

**페르소나: Java/Spring 학습자**

- 목표: 피드백 분석 앱을 통해 입력 계약, 테스트 설계, 레이어 분리, 회귀 보호를 학습한다.
- 상황: README와 기존 기능을 기준으로 수동 입력, CSV 업로드, 감정 분석, 키워드 분류, 필터링, 시각화, 다운로드 요구사항을 정리해야 한다.
- Pain: 기능은 존재하지만 입력 오류, 분석 기준, 출력 계약, 회귀 보호 규칙이 명확하지 않다.

### 2.2 주요 시나리오

- 학습자는 수동 입력 화면에서 `"복숭아 최고"`를 입력하고 분석을 요청한다. 시스템은 피드백을 저장하고 감정 결과를 `"긍정"`으로 집계하며 키워드 카테고리 카운트는 증가시키지 않는다.
- 학습자는 `text` 컬럼이 포함된 CSV를 업로드한다. 시스템은 CSV 행을 피드백으로 수용하고 감정 및 키워드 기준으로 분석한다.
- 학습자는 분석된 결과를 감정과 키워드 기준으로 필터링하고, 화면에 표시된 필터 결과를 CSV로 다운로드한다.

| 감정 분석 | 피드백 텍스트 | `"긍정"`, `"부정"`, `"중립"` 중 하나의 집계 결과 |
| 키워드 분류 | 피드백 텍스트 | `"배송"`, `"품질"`, `"가격"`, `"서비스"`, `"사용성"` 카테고리 집계 |
| 필터링 | 감정 값과 키워드 값 | 두 조건을 모두 만족하는 피드백 목록 |
| 검색 | 검색어 문자열 | 검색어를 포함한 피드백 목록 |
| 시각화 | 분석 완료된 피드백 집계 | 감정 요약과 키워드 카테고리 요약 |
| CSV 다운로드 | 필터링된 피드백 결과 | UTF-8 CSV 파일, 첫 행 `text`, 이후 필터 결과 행 |

### 3.3 제약 사항

Phase 4 Gherkin Background와 동일한 전제를 사용한다.

```gherkin
Given 고객이 수동 입력 혹은 CSV 입력으로 피드백을 제공할 수 있다
And 시스템은 피드백 텍스트를 감정과 키워드 기준으로 분석한다
```

- 입력 방식은 수동 입력 또는 CSV 입력이다.
- CSV 입력은 필수 컬럼 `text`를 포함해야 한다.
- `text` 컬럼에는 피드백 내용이 포함되어야 한다.
- 빈 문자열과 공백-only 문자열은 분석 대상에 추가하지 않는다.
- `"복숭아 최고"`는 유효한 피드백이며 `"최고"` 때문에 감정 결과는 `"긍정"`이다.
- `"복숭아 최고"`의 `"복숭아"`는 키워드 카테고리 비대상 단어이므로 키워드 카테고리 카운트를 증가시키지 않는다.
- `"복숭아를 먹었다"`는 감정표현 비대상 단어와 키워드 비대상 단어만 포함하므로 감정 결과는 `"중립"`이며 키워드 카테고리 카운트는 증가하지 않는다.
- `"parsec:1.0"`은 일반 텍스트 피드백으로 처리하며 단위 변환 오류로 처리하지 않는다.
- 긍정/부정 감정 키워드가 없는 입력은 `"중립"`으로 집계한다.
- 키워드 카테고리는 `"배송"`, `"품질"`, `"가격"`, `"서비스"`, `"사용성"`을 대상으로 한다.

## 4. 비기능 요구사항

### 4.1 기술 스택

- Java 21
- Gradle 또는 Maven
- JUnit 5
- Spring Boot
- Thymeleaf

### 4.2 아키텍처 원칙

- OCP: 새 감정 키워드, 새 키워드 카테고리, 새 분석 단위 추가 시 기존 공개 계약을 변경하지 않는다.
- SRP: 입력 검증, 분석, 필터링, 출력 책임은 각각 독립적으로 검증 가능한 책임으로 분리한다.
- BCE 레이어: Boundary는 입력과 출력 계약을 담당하고, Control은 사용자 흐름을 조정하며, Entity는 피드백 데이터와 분석 결과 의미를 보존한다.
- 의존성 방향: 화면과 입출력 흐름은 분석 규칙에 의존할 수 있으나, 분석 규칙은 화면 표현 방식에 의존하지 않는다.
- 회귀 보호: 공개 동작 변경은 Story Acceptance Criteria와 Gherkin Scenario 갱신 후에만 허용한다.

### 4.3 테스트 커버리지 목표

| 영역 | 목표 |
|---|---|
| Domain | 핵심 도메인 로직 라인 커버리지 80% 이상 |
| Boundary | 수동 입력, CSV 입력, 필터링, 다운로드 계약 테스트 100% 통과 |
| Data | `text` 필수 컬럼, UTF-8 CSV 다운로드, 한글 피드백 보존 검증 100% 통과 |
| Branch | 입력 검증, 분류, 감정 분석 주요 분기 커버리지 90% 이상 |

### 4.4 확장성 원칙

- 새 키워드 카테고리 추가 시 기존 감정 분석 계약을 변경하지 않는다.
- 새 감정 키워드 추가 시 기존 CSV 입력 및 다운로드 계약을 변경하지 않는다.
- 새 분석 단위 등록 시 기존 피드백 입력 문자열의 의미를 변경하지 않는다.
- 저장소 범위 밖 단위 문자열은 일반 피드백 텍스트로 처리한다.
- 확장 기능은 기존 Gherkin 시나리오가 통과하는 상태에서만 수용한다.

- 수동 입력
- CSV 입력

### 5.2 입력 내용

- 입력 내용에는 키워드 관련 단어가 포함될 수 있다.
- 입력 내용에는 키워드 관련 단어가 포함되지 않을 수 있다.
- 입력 내용에는 감정 관련 단어가 포함될 수 있다.
- 입력 내용에는 감정 관련 단어가 포함되지 않을 수 있다.
- 감정 관련 단어와 키워드 관련 단어가 모두 없으면 피드백은 유효하게 처리하고 감정은 `"중립"`으로 집계한다.
- 감정 관련 단어와 키워드 관련 단어가 모두 없으면 키워드 카테고리 카운트는 증가하지 않는다.

## 6. 출력 요구사항

### 6.1 피드백 분석결과 시각화

- 감정별 집계를 화면에 표시한다.
- 키워드 카테고리별 집계를 화면에 표시한다.
- 입력 또는 CSV 업로드 직후 최신 분석 결과를 반영한다.
- 필터 적용 후 시각화는 필터링된 데이터 기준으로 갱신한다.
- 데이터가 없을 때 시각화 영역은 오류 없이 빈 상태 또는 0값 상태를 표시한다.

### 6.2 CSV 출력 및 다운로드

- 필터링된 결과를 CSV로 다운로드할 수 있어야 한다.
- CSV 첫 행은 `text` 헤더여야 한다.
- CSV는 UTF-8로 다운로드되어야 한다.
- CSV의 한글 피드백은 깨지지 않아야 한다.
- 다운로드 데이터는 화면의 필터 결과와 일치해야 한다.
- 필터 결과가 없으면 빈 CSV 제공 또는 다운로드 제한 안내 중 하나의 정책을 명시해야 한다.

## 7. 성공 지표

### 7.1 인수 기준

- [ ] `"복숭아 최고"` 입력 시 피드백이 저장되고 감정 결과가 `"긍정"`으로 집계되며 키워드 카테고리 카운트는 증가하지 않는다.
- [ ] 빈 입력 또는 공백-only 입력 시 피드백이 저장되지 않고 기존 분석 결과가 유지된다.
- [ ] `text` 컬럼이 포함된 CSV 업로드 시 각 행이 피드백으로 수용되고 분석 결과에 반영된다.
- [ ] 감정 `"부정"`과 키워드 `"가격"` 필터를 함께 적용하면 두 조건을 모두 만족하는 피드백만 표시된다.
- [ ] CSV 다운로드 시 첫 행은 `text`이고 한글 피드백은 UTF-8로 보존된다.

### 7.2 회귀 보호 규칙

- 공개 입력 계약 변경 금지: 수동 입력, CSV `text` 컬럼, 감정 값, 키워드 카테고리 계약은 Story와 Gherkin 갱신 없이 변경하지 않는다.
- 공개 출력 계약 변경 금지: 감정 집계, 키워드 집계, 필터 결과, CSV `text` 헤더는 인수 기준 갱신 없이 변경하지 않는다.
- 결함 수정 규칙: 버그 수정 전 실패 재현 테스트를 먼저 추가한다.
- 병합 규칙: Story Acceptance Criteria와 Gherkin Scenario가 현재 동작과 불일치하면 병합하지 않는다.
- 확장 규칙: 새 분석 단위 추가는 기존 Phase 4 Gherkin 시나리오를 모두 통과해야 한다.
