## 📋 회귀 방지 체크리스트

### 입력 계약

- [ ] 수동 입력은 비어 있지 않은 피드백 텍스트만 분석 대상에 추가한다.
- [ ] 빈 문자열과 공백-only 문자열은 분석 대상에 추가하지 않는다.
- [ ] 특수문자만 있는 입력의 처리 정책과 예외 메시지를 테스트로 고정한다.
- [ ] null 입력의 처리 정책과 예외 메시지를 테스트로 고정한다.
- [ ] CSV 입력은 첫 행에 `text` 헤더를 포함해야 한다.
- [ ] CSV의 `text` 컬럼에는 피드백 내용이 포함되어야 한다.

### 분석 계약

- [ ] 감정 분석 결과는 `긍정`, `부정`, `중립` 중 하나로 집계한다.
- [ ] 긍정/부정 감정 키워드가 없는 입력은 `중립`으로 집계한다.
- [ ] `복숭아 최고` 입력 시 감정 결과는 `긍정`으로 집계한다.
- [ ] `복숭아 최고`의 `복숭아`는 키워드 카테고리 카운트를 증가시키지 않는다.
- [ ] `복숭아를 먹었다`는 `중립`으로 집계하고 키워드 카테고리 카운트를 증가시키지 않는다.
- [ ] 중복 키워드 제거 후에도 기존 감정/키워드 분석 결과가 유지된다.

### 필터링 계약

- [ ] 감정 필터와 키워드 필터를 함께 적용하면 두 조건을 모두 만족하는 피드백만 표시한다.
- [ ] 감정 `부정`과 키워드 `가격` 필터 조합의 결과를 테스트로 고정한다.
- [ ] 필터 결과가 없을 때 사용자에게 일관된 안내를 제공한다.
- [ ] 필터 적용 후 시각화는 필터링된 데이터 기준으로 갱신한다.

### 출력 계약

- [ ] CSV 다운로드 첫 행은 `text` 헤더여야 한다.
- [ ] CSV 다운로드는 UTF-8로 제공되어야 한다.
- [ ] CSV의 한글 피드백은 깨지지 않아야 한다.
- [ ] 다운로드 데이터는 화면의 필터 결과와 일치해야 한다.
- [ ] 필터 결과가 없을 때 빈 CSV 제공 또는 다운로드 제한 안내 중 하나의 정책을 명시한다.

### 아키텍처 계약

- [ ] Boundary는 입력과 출력 계약을 담당한다.
- [ ] Control은 사용자 흐름을 조정한다.
- [ ] Entity는 피드백 데이터와 분석 결과의 의미를 보존한다.
- [ ] 분석 규칙은 화면 표현 방식에 의존하지 않는다.
- [ ] 공개 동작 변경 시 Story Acceptance Criteria와 Gherkin Scenario를 먼저 갱신한다.
