# 01_코드분석 및 .cursorrules 작성 보고서 - Prompting

## 1. 목적

이 문서는 이번 세션에서 사용한 사용자 요청과 작업 프롬프트 흐름을 기록한다.

작업 목표:

- 코드베이스 전체 구조와 미션 분석
- 분석 내용을 `docs/PRD.md`로 문서화
- `project_purpose.md`, `docs/PRD.md`, 현재 코드베이스를 반영한 `.cursorrules` 작성
- 세션 작업 내용을 보고서와 프롬프트 기록으로 내보내기

## 2. 사용자 요청 프롬프트

### 2.1 코드베이스 분석 요청

```text
@Codebase 전체구조·미션안내분석해줘
```

의도:

- 저장소 전체 구조 파악
- 프로젝트의 목적과 미션 파악
- 주요 소스 파일과 실행 흐름 분석
- 리팩토링 관점의 문제점 도출

### 2.2 PRD 문서화 요청

```text
정리된 내용을 docs/PRD.md 문서로 내보내줘
```

의도:

- 앞선 코드 분석 결과를 문서화
- 제품 목적, 기능, 구조, 리팩토링 방향을 PRD 형식으로 정리
- `docs/PRD.md` 파일 생성

### 2.3 .cursorrules 작성 요청

```text
현재 코드베이스와 docs/PRD.md ,@project_purpose.md 를 참조해서 .cursorrules 파일을 핵심만 정리해서 만들어줘
```

의도:

- 프로젝트 전용 Cursor 작업 규칙 생성
- 이후 AI가 코드 수정 시 지켜야 할 핵심 지침 정리
- 문서와 실제 코드베이스를 함께 반영
- 너무 장황하지 않게 핵심만 유지

### 2.4 보고서 및 프롬프트 기록 요청

```text
이번세션에서 진행한 내용을 report 폴더의 01_코드분석 및 .cursorrules 작성_보고서 파일로 내보내주고, 
프롬프트를 포함해서 Prompting 폴더의 01_코드분석 및 .cursorrules 작성_보고서-Prompting.md 파일로 내보내줘
```

의도:

- 이번 세션에서 수행한 분석과 생성 파일을 보고서로 남김
- 사용한 프롬프트 흐름도 별도 문서로 보관
- `report`와 `Prompting` 폴더에 산출물 저장

## 3. 코드베이스 분석용 작업 프롬프트

코드베이스 분석 단계에서는 다음 관점으로 저장소를 탐색했다.

```text
Explore the repository and summarize its overall structure and apparent mission/purpose.

Inspect:
- top-level files
- README and project purpose documents
- Maven configuration
- Spring Boot entry points
- controllers, services, domain classes
- Thymeleaf templates
- tests

Return:
1. project mission/product purpose
2. architecture/tech stack
3. key directories/files and responsibilities
4. main execution flows
5. notable risks or gaps
```

이 프롬프트를 통해 다음 파일을 중심으로 분석했다.

- `README.md`
- `project_purpose.md`
- `pom.xml`
- `src/main/java/com/example/demo/FeedbackController.java`
- `src/main/java/com/example/demo/TextAnalyzer.java`
- `src/main/java/com/example/demo/Filters.java`
- `src/main/java/com/example/demo/Constants.java`
- `src/main/java/com/example/demo/Session.java`
- `src/main/resources/templates/index.html`
- `src/test/java/com/example/demo/DemoApplicationTests.java`

## 4. PRD 작성용 프롬프트 구조

`docs/PRD.md` 작성 시 사용한 내부 정리 기준은 다음과 같다.

```text
Write a PRD for the Feedback Analyzer project based on the codebase analysis.

Include:
- product overview
- user-facing mission
- learning/refactoring mission
- target users
- core features
- current architecture
- directory structure
- main user flows
- known issues and risks
- refactoring direction
- success criteria
- open questions

Keep the document useful for both developers and learners.
```

작성 결과 `docs/PRD.md`에는 다음 섹션을 포함했다.

- Product Overview
- Product Mission
- Target Users
- Core Features
- Current Architecture
- Main User Flows
- Known Issues And Risks
- Refactoring Direction
- Success Criteria
- Open Questions

## 5. .cursorrules 작성용 프롬프트 구조

`.cursorrules` 작성 시 사용한 내부 정리 기준은 다음과 같다.

```text
Create a concise .cursorrules file for this project.

Use:
- current codebase structure
- docs/PRD.md
- project_purpose.md

Focus on:
- project context
- product mission
- architecture direction
- implementation guidelines
- testing expectations
- documentation expectations

Keep it short and actionable. Do not duplicate the full PRD.
```

최종 `.cursorrules`에는 다음 핵심 규칙을 담았다.

- 고객 피드백 분석기이자 리팩토링 챌린지라는 프로젝트 맥락
- 핵심 사용자 흐름 보존
- 감정/카테고리 값의 기준
- 컨트롤러 책임 축소
- 분석 규칙 단일 출처화
- static mutable state 추가 금지
- 명확한 도메인 타입 우선
- 테스트 우선순위
- 문서 동기화 기준

## 6. 보고서 작성용 프롬프트 구조

이번 보고서 작성 시 사용한 정리 기준은 다음과 같다.

```text
Export the work completed in this session as a report.

Include:
- session overview
- referenced files
- codebase analysis summary
- major issues found
- PRD summary
- .cursorrules summary
- recommended next steps
- final deliverables

Also create a separate prompting document that includes user prompts and the internal prompt structure used to produce the outputs.
```
