# 06. PRD 작성 보고서 Prompting

## 1. 목적

이 문서는 `feedback_analyzer_A02` 저장소를 대상으로 이번 세션에서 작성한 PRD 산출물의 사용자 프롬프트, 해석 기준, 최종 산출물 구성을 보관하기 위한 Prompting 기록이다.

핵심 목표는 Phase 4 Epic/Story/Gherkin을 기반으로 제품 요구사항 문서를 작성하는 것이다. 코드, 클래스 설계, 빌드 스크립트는 포함하지 않는다.

## 2. 세션 프롬프트 원문

### Prompt 1. PRD 작성 요구

```text
당신은 PRD 전문가입니다. 워크스페이스: @
⚠️ 코드·클래스 설계·빌드 스크립트는 작성하지 마십시오.
전제: Phase 4 Epic/Story/Gherkin을 기반으로 작성하라.

# 1. 프로젝트 개요
  1.1 한 줄 목적문 (What/Who/Why)
  1.2 배경 및 문제 정의 (현재 코드: 단일 main, if-else 체인)
  1.3 목표 3~5개 (측정 가능)
  1.4 비목표 2~3개

# 2. 사용자 및 이해관계자
  2.1 타깃 사용자 (페르소나 1개)
  2.2 주요 시나리오 2~3개 (Phase 4 Journey 기반)

# 3. 기능 요구사항
  3.1 기능 목록 (필수/권장/선택 구분)
      - 필수: 입력 검증, CSV 출력
      - 권장: OCP 레지스트리, 동적 단위 등록
  3.2 기능별 입출력 계약 (문자열 계약 수준, 코드 X)
  3.3 제약 사항 (입력 형식, 감정표현 비대상 단어, 키워드 비대상 단어)
  → Phase 4 Gherkin의 Background Given과 반드시 일치

# 4. 비기능 요구사항
  4.1 기술 스택: Java 21, Gradle/Maven, JUnit 5, Spring-boot, thymeleaf
  4.2 아키텍처 원칙 (OCP/SRP, BCE 레이어, 의존성 방향)
  4.3 테스트 커버리지 목표 (Domain/Boundary/Data 수치)
  4.4 확장성 원칙 (새 단위 추가 시 기존 코드 변경 최소화)

# 5. 데이터 요구사항
  5.1 입력방식은 수동입력 혹은 CSV 입력
  5.2 입력내용에 키워드, 감정 관련 단어는 포함될수도 있고 아닐수도 있음

# 6. 출력 요구사항
  6.1 피드백 분석결과 시각화
  6.2 CSV 출력 및 다운로드

# 7. 성공 지표
  7.1 인수 기준 3~5개 (체크박스, 테스트 가능)
  7.2 회귀 보호 규칙 (계약 변경 금지 정책)

# 8. 용어 정의 (Glossary) — 5개 이상

출력: 구조화된 Markdown만. 모호어("적절히") 금지.
```

## 5. Phase 4 정합성 기준

### 5.1 Background Given

PRD의 제약 사항은 다음 Phase 4 Gherkin Background와 일치하도록 작성했다.

```gherkin
Given 고객이 수동 입력 혹은 CSV 입력으로 피드백을 제공할 수 있다
And 시스템은 피드백 텍스트를 감정과 키워드 기준으로 분석한다
```

### 5.2 Story 추적성

| Story ID | PRD 반영 내용 |
|---|---|
| ST-01 | 입력 검증, 빈 입력, CSV 형식 오류, 기존 분석 결과 유지 |
| ST-02 | 키워드 유무 기반 피드백 분류, 비대상 단어 정책 |
| ST-03 | 감정 분석, 긍정/부정/중립 계약, 비대상 감정 단어 정책 |
| ST-04 | 감정과 키워드 기준 필터링, 검색 계약 |
| ST-05 | 감정별/키워드별 시각화 출력 요구사항 |
| ST-06 | CSV 다운로드, UTF-8, `text` 헤더, 필터 결과 일치 |

## 7. 최종 PRD 요약

### 7.1 프로젝트 목적

고객 피드백을 입력하는 학습자가 수동 입력 또는 CSV 입력으로 피드백을 제공하면, 시스템은 감정과 키워드 기준으로 분석하고 시각화 및 CSV 다운로드 결과를 제공한다.

### 7.2 기능 요구사항 요약

| 구분 | 기능 |
|---|---|
| 필수 | 입력 검증 |
| 필수 | CSV 출력 및 다운로드 |
| 필수 | 키워드 유무 기반 피드백 분류 |
| 필수 | 감정 분석 |
| 필수 | 피드백 필터링 및 검색 |
| 필수 | 분석 결과 시각화 |
| 권장 | OCP 레지스트리 기반 분석 규칙 확장 |
| 권장 | 동적 분석 단위 등록 |
| 선택 | 잘못된 JSON/YAML 설정 파일 오류 보고 |

### 7.3 테스트 가능한 성공 지표

- [ ] `"복숭아 최고"` 입력 시 피드백이 저장되고 감정 결과가 `"긍정"`으로 집계되며 키워드 카테고리 카운트는 증가하지 않는다.
- [ ] 빈 입력 또는 공백-only 입력 시 피드백이 저장되지 않고 기존 분석 결과가 유지된다.
- [ ] `text` 컬럼이 포함된 CSV 업로드 시 각 행이 피드백으로 수용되고 분석 결과에 반영된다.
- [ ] 감정 `"부정"`과 키워드 `"가격"` 필터를 함께 적용하면 두 조건을 모두 만족하는 피드백만 표시된다.
- [ ] CSV 다운로드 시 첫 행은 `text`이고 한글 피드백은 UTF-8로 보존된다.
